Khoa Công Nghệ Thông Tin

Bối cảnh & Vấn đề thị trường

  • Khủng hoảng thông tin: Khách mất quá nhiều thời gian "nhảy tab" giữa các trang tìm tour, khách sạn rời rạc.
  • Bottleneck (Nghẽn cổ chai): Kiến trúc Web cũ (Client-Server) dễ sập nguồn do quá tải server lúc cao điểm mùa du lịch.
  • Thiếu cá nhân hóa: Các form tìm kiếm hiện nay cứng nhắc, chưa thể tư vấn linh hoạt theo ngữ cảnh của từng khách hàng.

Thiết Kế CSDL: Tại sao chọn NoSQL?

SQL Truyền Thống vs NoSQL

  • CSDL Quan hệ (SQL): Phải tách rời Bảng. Khi cần lấy dữ liệu tổng hợp, hệ thống phải chạy lệnh JOIN liên tục gây chậm trễ.
  • Mô hình NoSQL: Dùng Data Embedding (Kỹ thuật lồng dữ liệu). Mảng Khách sạn & Xe được nhúng thẳng vào file JSON gốc.
  • Single Query (Truy vấn duy nhất): Gọi DB 1 lần là có đủ dữ liệu. Giúp hệ thống đạt mức Low-latency (Độ trễ cực thấp).

1. Auth Observer (Lắng nghe Real-time)

Ủy quyền cho Firebase mã hóa Token. Hàm liên tục bắt tín hiệu ngay khi phiên đăng nhập hết hạn hoặc thay đổi.

2. Chốt chặn vòng ngoài

Ngay tại trình duyệt, nếu phát hiện Token rỗng, lập tức điều hướng khách về trang đăng nhập.

3. Đối chiếu Vai trò (Authorization)

Dùng UID an toàn chọc vào Collection `users` để kiểm tra quyền hạn thực sự của tài khoản.

4. Khóa quyền Admin

Chỉ khi biến `role` khớp với chuỗi "admin" thì giao diện quản trị (Dashboard) mới được phép Render.
