Khoa Công Nghệ Thông Tin

Bối cảnh & Vấn đề thị trường

  • Khủng hoảng thông tin: Khách mất quá nhiều thời gian nhảy tab giữa các trang tìm tour, khách sạn rời rạc.
  • Bottleneck (Nghẽn cổ chai máy chủ): Kiến trúc Web cũ (Client-Server) dễ sập nguồn lúc cao điểm mùa du lịch.
  • Thiếu cá nhân hóa: Các form tìm kiếm hiện nay cứng nhắc, không thể tư vấn theo ngữ cảnh (Context) của từng khách hàng.

Thiết Kế CSDL: Tại sao chọn NoSQL?

SQL Truyền Thống vs NoSQL

  • CSDL Quan hệ (SQL): Phải tách rời Bảng. Khi cần lấy dữ liệu Tour, hệ thống phải chạy lệnh JOIN liên tục gây chậm trễ.
  • Mô hình NoSQL: Dùng Data Embedding (Kỹ thuật lồng dữ liệu). Mảng Khách sạn & Xe được nhúng thẳng vào file JSON của Tour.
  • Single Query (Truy vấn duy nhất): Gọi DB 1 lần là có đủ dữ liệu. Giúp hệ thống Read-heavy (Ưu tiên tốc độ đọc) đạt mức Zero-latency (Độ trễ bằng 0).

1. Lắng nghe ngầm Real-time

Ủy quyền cho Firebase tự mã hóa Token. Hàm bắt tín hiệu ngay khi phiên đăng nhập hết hạn hoặc thay đổi.

2. Chốt chặn vòng ngoài

Ngay tại trình duyệt, nếu phát hiện Token rỗng, lập tức điều hướng về trang đăng nhập.

3. Đối chiếu Role (Vai trò)

Dùng UID an toàn chọc vào Collection `users` để kiểm tra phân quyền (Authorization).

4. Khóa quyền Admin

Chỉ khi biến `role` khớp với chuỗi "admin" thì giao diện quản trị mới được phép Render (Hiển thị).
